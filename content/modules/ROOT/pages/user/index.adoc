This section takes you from a web address and a token to a working chat with an AI agent that your team runs for you.
All you need is a browser; you don't need any access to the cluster.

== What OpenClaw is

OpenClaw is an open-source AI agent.
An agent does more than answer questions: it acts on your behalf by calling tools, which are functions that let it read data, change files, or run commands.
An agent that acts for you can hold credentials and run commands on real computers, so where it runs and what it may reach matter.

You reach OpenClaw through its gateway, the OpenClaw process that runs the agent on the cluster.
The gateway serves the Control UI, a web app that opens right in your browser, so there's nothing to install.
From the Control UI you chat with the agent and follow the work it does.

== What the agent can do here

The agent has a workspace, the working directory its file tools use, so it can read and change files there for you.
It can call the tools your team allows.
This deployment switches off web search, web fetch, and browser tools, and it connects no messaging channels, so the Control UI is the only way to reach the agent.

== Why it runs on your team's platform

Your team runs OpenClaw on its own OpenShift cluster, and this deployment is built to use a model that your team serves there.
That keeps the agent's state, memory, and credentials on your team's own infrastructure.
Your prompts go to the model provider your team configured, plus any diagnostics export it turns on, and OpenClaw has no hosted service of its own that would receive them.

== What to ask your administrator for

Before you can connect, ask the person who set up the deployment for three things.

The web address of the Control UI::
This is the link you open in your browser to reach the agent.

The gateway token::
You paste this token when the Control UI asks you to connect, and it's what lets you in.

Approval for your browser::
When you open the deployment's web address on the cluster, the gateway treats your browser as a remote connection and asks for it to be approved.
Your administrator approves it, and then you reach the chat.
When your administrator forwards the gateway to your own machine and you open a `localhost` address instead, the gateway approves your browser on its own.

Once you have the address, paste the token, and your browser is approved, the chat interface is ready to use.
