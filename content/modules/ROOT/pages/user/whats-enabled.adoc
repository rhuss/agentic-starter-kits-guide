OpenClaw can do a lot more than this deployment lets it.
The recipe ships a focused configuration that turns several features off, so the agent stays inside the boundaries your team set for it.
This page walks through what is switched off and what that means for you, and it points you to the one thing that can change any of it: your administrator.

== No web search, web fetch, or browser tools

The recipe tells the gateway to deny two sets of tools, written as `tools.deny: [group:web, browser]`.
`group:web` is a shorthand that stands for the `web_search`, `x_search`, and `web_fetch` tools, so denying it takes all three away at once.
Denying `browser` removes the tool that would let the agent drive a web browser on your behalf.

In practice this means the agent cannot search the web, open a web page, or control a browser for you.
A denied tool is a hard stop: even if the model tries to call one, the gateway refuses it, because a deny rule always wins.
If you ask the agent to look something up online, it has no web tool to call.

== No messaging channels

The recipe sets `channels: {}`, which means no messaging channels are connected.
Channels are the links that would let the agent talk to you through an outside platform such as a chat app.

Because there are none, the only way you reach the agent is the Control UI in your browser, which you set up in xref:user/connect.adoc[Connect and pair your browser].
There is no separate inbox, phone number, or chat handle to watch.

== The agent runs without a separate sandbox

The recipe sets the agent's sandbox mode to off (`sandbox: {mode: off}`).
With sandboxing off, the agent's tools run directly on the host where the gateway runs rather than in a separate, isolated sandbox.

For you, this changes nothing you can see in the chat: you send a message and read the reply the same way either way.
Running the agent inside its own sandbox is a separate capability that an administrator sets up when a deployment needs it.

== No proactive heartbeat messages

Heartbeat is a background feature that would wake the agent on a timer (every 30 minutes by default) to check whether anything needs your attention, then send you a short note if it does.
Those notes are delivered to an owner address, which OpenClaw finds from a configured owner entry or messaging channel.

Since this deployment configures no channels and no owner address, heartbeat has nowhere to send a message, so each scheduled check is skipped before the agent even runs.
On top of that, the default heartbeat instruction tells the agent to stay quiet and reply with nothing when there is nothing to report.
The practical result is that the agent does not message you on its own: it answers when you talk to it, and otherwise stays silent.

== What an administrator can change for you

Every setting on this page lives in the gateway's configuration, and an administrator can change it on a running deployment.
If you need a feature that is currently off, that is who to ask.

For example, an administrator can allow a web tool you need, connect a messaging channel, turn on sandboxing, or set up heartbeat delivery.
Most settings apply to the running gateway without a manual restart, and the gateway restarts by itself when a change needs it.
The steps are in xref:admin/change-config.adoc[Change the configuration of a running gateway].
When you ask, name the specific tool or feature you want, so the administrator knows exactly which setting to adjust.
